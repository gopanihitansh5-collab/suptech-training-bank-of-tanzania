8. Important product and data safeguards
Synthetic data must be clearly labelled in the UI, reports, exports, seed scripts and assistant responses.
World Bank public indicators are country-level contextual data; do not merge them into institution-level records as though they were the same type of evidence.
A threshold breach is a review signal, not an automatic finding of misconduct or regulatory non-compliance.
Do not make up official Bank of Tanzania thresholds, policies, institution names or live statistics.
Never expose uploaded files across users or institution scopes. Apply access filters before retrieval, not after the LLM has seen the content.
Do not run arbitrary SQL generated by an LLM. Use allowlisted functions and parameterised queries.
Do not let agents autonomously change supervisory records, resolve exceptions, distribute reports or change permissions without explicit user authorization.
Back up an existing database before approved migrations. Never reset a database to make a demo pass.
Use provider abstractions for LLM and embedding models. If no key is configured, keep deterministic non-LLM functions operational and display a clear configuration status.
Keep an honest feature matrix. A polished UI must never disguise an unimplemented backend.
