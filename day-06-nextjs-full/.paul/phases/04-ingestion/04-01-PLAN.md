<objective>
## Goal
Implement opt-in, local-only TXT/CSV ingestion for synthetic training
documents, with strict validation, checksums, persisted job state, provenance,
and safe deletion.

## Purpose
Make the Data Explorer's ingestion workspace useful without accepting
confidential records, executing file content, or treating uploaded content as
trusted instructions.

## Output
An authenticated upload/list/delete/retry workflow, safe local file storage,
bounded text/CSV parsing and chunks, audit events, focused tests and updated
documentation.
</objective>

<acceptance_criteria>

## AC-1: Explicit local upload gate
```gherkin
Given demo uploads are disabled by default
When a user without a supervisor/admin demo role or without
ENABLE_DEMO_UPLOADS=true attempts an upload
Then the server rejects the request before writing files or database rows
```

## AC-2: Strict bounded file handling
```gherkin
Given an authenticated user uploads a training file
When the file is not TXT or CSV, exceeds the configured maximum (capped at
10 MB), has an invalid UTF-8 body, malformed CSV, or too many rows
Then the server returns a clear client error and stores no partial document
```

## AC-3: Provenance and duplicate safety
```gherkin
Given a valid synthetic TXT or CSV upload
When ingestion completes
Then the app stores it outside the public directory under a server-generated
name, records its SHA-256 checksum, job status, source scope and audit event,
and persists bounded text chunks with source references
And re-uploading identical bytes returns an explicit duplicate conflict
```

## AC-4: Safe retry and deletion
```gherkin
Given an uploaded document or failed job
When an authorized user retries or deletes it
Then processing uses the verified stored file and deletion can only remove
that document's server-generated path and dependent records
And the action is recorded in the audit log
```

<boundaries>

## DO NOT CHANGE
- Existing Python Day 1–3 source and their tests.
- Existing PostgreSQL port-5432 database.
- Extracted Stitch assets or other user changes.

## SCOPE LIMITS
- Accept synthetic training data only; never upload confidential supervisory
  data or personal information.
- Support only TXT and CSV. Reject PDF, DOCX, XLSX, JSON, archives, macros and
  executable formats.
- Keep storage outside `public/`, use generated names and cap files at 10 MB.
- Do not use any public model provider or process file contents with an LLM.
- Uploaded text is untrusted; no instruction in a file can authorize an action.

</boundaries>
