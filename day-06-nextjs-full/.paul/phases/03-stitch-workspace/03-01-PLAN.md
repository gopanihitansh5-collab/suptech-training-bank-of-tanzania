<objective>
## Goal
Make all nine supervisory workspace modules reachable and useful in the shared
Next.js shell, using persisted synthetic data where available and explicit
capability boundaries elsewhere.

## Purpose
Turn the remaining Stitch navigation concepts into honest, navigable screens
without presenting mockup content as Bank of Tanzania data or implying that
later-phase features already work.

## Output
Five additional pages for report preview, data exploration, assistant
capabilities, system health, and administration; validated report-list
services; functional navigation and filters; focused verification and docs.

<acceptance_criteria>

## AC-1: Nine reachable modules
```gherkin
Given the user has a valid local demo session
When they use the shared navigation
Then Overview, Institutions, Analytics, Exceptions, Reports, Data Explorer,
Assistant, System Health, and Administration each open a page in the shared shell
```

## AC-2: Persisted report exploration
```gherkin
Given synthetic reports exist in the Day 6 database
When the user filters the data explorer or report preview by period, institution,
or search text
Then the screen shows matching persisted report metadata with bounded paging
And malformed filters produce explicit validation errors
```

## AC-3: Honest capability surfaces
```gherkin
Given ingestion, assistant retrieval, report export, and administration writes
belong to later phases
When the user opens those module pages
Then the screen distinguishes available functionality from planned functionality
And does not show fabricated data, active dead-end controls, or production claims
```

## AC-4: Health and responsive use
```gherkin
Given the user opens System Health on the local training app
When the database probe runs
Then the page reports only the observed Day 6 database status and clearly labels
model and external integrations as not connected unless actually integrated
And the new pages use the shared narrow-viewport layout rules
```
